## ❌ KHÔNG chạy được — dòng lỗi thật

### 1. `cargo-scout-audit` — không build được (C dependency)

Thử hai đường theo đúng gợi ý:

```
$ cargo install cargo-scout-audit --features vendored-openssl
error: failed to compile `cargo-scout-audit v0.3.16`
Caused by:
  the package 'cargo-scout-audit' does not contain this feature: vendored-openssl
```

→ feature đó KHÔNG tồn tại ở 0.3.16 (đợt trước ghi "fail openssl" là mô tả thiếu chính xác).

```
$ OPENSSL_STATIC=1 cargo install cargo-scout-audit
  --- stderr
  error occurred in cc-rs: command did not execute successfully (status code exit status: 1):
  LC_ALL="C" "cc" "-O3" ... "-DNGHTTP2_STATICLIB" ...
  "-o" ".../64375acaab57ea54-sfparse.o" "-c" "nghttp2/lib/sfparse.c"
error: failed to compile `cargo-scout-audit v0.3.16`
```

→ Nghẽn thật KHÔNG phải openssl mà là **libnghttp2-sys** biên dịch C thất bại (thiếu
header/toolchain C của hệ thống). Gỡ được bằng cách cài dev package hệ thống — quyền
sudo, không có trên máy build. **Ghi vào BLOCKERS.**

### 2. OZ `soroban-scanner` — panic UTF-8, LỖI UPSTREAM còn nguyên

Đã thử bản MỚI HƠN đợt trước (clone depth-1, commit `f3888e0` "Refactor detector ID
handling…"). Ghi chú: package đã đổi tên nên `-p soroban-scanner` không còn đúng
(`error: package ID specification 'soroban-scanner' did not match any packages`);
tên crate thật là `soroban-security-detectors-runner`, build bằng
`cargo build --release --manifest-path soroban-scanner/Cargo.toml` → **build XONG**.

Nhưng khi quét thì vẫn panic y như cũ:

```
$ soroban-scanner scan --project-root recovery-registry recovery-registry/src/lib.rs
thread 'main' (64541) panicked at sdk/src/ast_types_builder.rs:254:60:
Invalid UTF-8 sequence: FromUtf8Error { bytes: [97, 195, 40, 100],
  error: Utf8Error { valid_up_to: 1, error_len: Some(1) } }
```

**Đây là bug của tool, KHÔNG phải comment tiếng Việt trong source** (đợt trước đã tái
hiện trên source ASCII thuần; kết luận đó vẫn đứng). Bằng chứng thêm: chuỗi byte
`[97, 195, 40, 100]` = `'a'`, `0xC3`, `'('`, `'d'` — `0xC3` là byte MỞ ĐẦU của một ký
tự 2-byte nhưng byte tiếp theo là `'('`, không phải continuation byte. Tức tool đang
**cắt một dãy byte giữa ký tự** rồi mới `String::from_utf8`, lỗi offset của chính nó.

⚠️ **Bẫy phải nêu:** gọi không kèm đường dẫn file thì tool KHÔNG panic mà trả

```json
{ "errors": [], "scanned": [], "detector_responses": {} }
```

`scanned: []` = **không quét file nào**. Đọc nhầm cái này thành "quét sạch, không phát
hiện gì" là tự lừa mình — nên ghi ra đây để lần sau không ai nhận nhầm.

## Thay bằng gì, và yếu ở đâu

`cargo-mutants` + `clippy` + `proptest` + grep panic-path thay cho hai tool trên.
**Yếu hơn ở đâu, nói thẳng:**

- Không có **detector chuyên Soroban** (scout/OZ mang sẵn luật kiểu "thiếu
  `require_auth`", "dùng temporary cho dữ liệu sống còn", "unchecked arithmetic").
  Mutants chỉ đo *test có bắt được thay đổi hành vi hay không* — nó KHÔNG biết luật
  bảo mật riêng của Soroban. Hai thứ không thay thế nhau.
- `proptest` kém `cargo-fuzz`: không coverage-guided mutation → dở ở đường sâu.
- Vì vậy **không** được đọc "mutants 181/226 caught" thành "contract đã audit sạch".

## Rà panic-path thủ công (thay phần detector unchecked-panic)

```
$ grep -rn "panic!\|\.unwrap()\|\.expect(" contracts/*/src/*.rs | grep -v "#\[cfg(test)\]"
```

Kết quả: **đúng MỘT chỗ còn lại** ngoài test (đã kiểm bằng lệnh trên, loại
`test.rs`/`proptests.rs`):

```
verifier-webauthn/src/lib.rs:104:        let flags = auth_data.get(32).unwrap();
```

`origin-verifier` (bản TÍCH HỢP, đường tiền đi thật) sạch — đợt 2 đã đổi hết sang
`panic_with_error!`, phần còn lại là `unwrap_or_else(|| panic_with_error!(...))`, tức
panic CÓ MÃ, đúng yêu cầu fuzz-safe.

Nhưng chỗ trên là **phát hiện thật, không phải nhiễu**, và nó nối với mutants:

- `.unwrap()` trần trên `auth_data` — dữ liệu do kẻ tấn công điều khiển hoàn toàn.
- Nó CHỈ an toàn nhờ cổng `auth_data.len() < 37` ở dòng 97 phía trên.
- Và mutant `97:28 replace < with >` ở đúng cổng đó **ĐANG CÒN SỐNG** (xem
  `mutants.txt`). Nghĩa là: không có test nào chốt cổng ấy, và nếu cổng sai thì
  `get(32).unwrap()` thành **panic trần** trên input thù địch.

Giảm nhẹ: `verifier-webauthn` là crate **SPIKE** (SDK 27, chứng minh gate-3 độc lập),
KHÔNG phải verifier cắm vào OZ smart account — bản đó là `origin-verifier`, và ở đó cổng
`< 37` đã được chốt bằng test mới trong closeout này
(`auth_data_shorter_than_37_rejected_with_its_own_code`). Vì vậy xếp 🟠 chứ không 🔴,
nhưng **vẫn phải vá** trước khi crate spike được dùng ở bất kỳ đường thật nào.
**Ghi vào BLOCKERS.**
